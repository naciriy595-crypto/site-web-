# Clifstone

E-commerce site for **Clifstone**, a Moroccan gothic streetwear-luxe brand
(watches, sunglasses, wallets, jewelry, accessories). Guest checkout only,
Cash on Delivery, free shipping, MAD currency, French/Arabic product content.

Stack: Next.js (App Router) + TypeScript + Tailwind CSS v4 + Prisma (SQLite) +
Zustand (cart) + a lightweight JWT-cookie admin auth (no external auth
provider needed).

## Getting started

```bash
npm install
cp .env.example .env   # then edit values as needed
npm run db:push        # creates the SQLite database from prisma/schema.prisma
npm run db:seed        # seeds categories, 4 products per category, admin user
npm run dev
```

Storefront: http://localhost:3000
Admin panel: http://localhost:3000/admin/login

Default admin login (from `.env` / seed — **change these in production**):

## Project structure

- `src/app/(store)/...` — storefront: homepage, `/shop/[category]`,
  `/product/[slug]`, `/cart`, `/checkout`, `/order/[id]`.
- `src/app/admin/...` — admin panel (protected by `src/proxy.ts`, the
  Next.js middleware/proxy convention): dashboard, product CRUD, order
  management.
- `src/app/api/...` — `/api/checkout` (guest order creation) and
  `/api/admin/*` (products, order status updates, CSV export).
- `prisma/schema.prisma` — `Category`, `Product`, `Order`, `OrderItem`,
  `AdminUser` models. `prisma/seed.ts` seeds everything, including product
  placeholder images generated by `scripts/generate-placeholders.mjs` into
  `public/products/`.

All product content (name, price, description, images, category, stock) is
editable from the admin panel — nothing is hardcoded in the frontend.

## Product images

Products ship with generated SVG placeholders so the store looks complete
out of the box. To use real photography, upload images anywhere (or drop
files into `public/products/`) and paste their URLs (one per line) into the
product form's "Images" field in the admin panel.

## WhatsApp order notifications

Every order is saved to the database regardless of what happens next. Per
project decision, notifications to **+212 640 848 752** use a **wa.me deep
link** (no Meta Business account / API token required):

- Right after a customer submits checkout, their browser opens a WhatsApp
  chat pre-filled with the full order summary, addressed to the store's
  number — they just tap send.
- The admin order detail page (`/admin/orders/[id]`) also has a
  "Envoyer / renvoyer sur WhatsApp" button that opens the same pre-filled
  message, for manual resend.

Message building lives in `src/lib/whatsapp.ts`. If you later get a Meta
WhatsApp Business/Cloud API account, swap `buildWhatsAppLink` for a
server-side `fetch` call to the Cloud API inside `src/app/api/checkout/route.ts`
— `META_WHATSAPP_TOKEN` / `META_WHATSAPP_PHONE_NUMBER_ID` env vars are
already reserved in `.env.example` for that.

## Ameex delivery integration

Ameex does not currently expose a documented public API we could integrate
against directly, so orders are prepared for **manual/CSV upload** instead:

- `/admin/orders` has an "Export CSV (Ameex)" button
  (`GET /api/admin/orders/export`, optionally `?status=NEW`) that downloads
  a CSV with the standard columns most Moroccan carriers ask for on manual
  bulk upload (recipient name, phone, city, address, product summary,
  quantity, COD amount, note).
- If you get Ameex API credentials later, replace the CSV route (or add a
  new one) with a server-side call to their order-creation endpoint using
  the same order data — the column names in
  `src/app/api/admin/orders/export/route.ts` document the field mapping to
  adjust.

## Notes on the logo

The Clifstone wordmark shown in chat was only shared as an inline image, not
as a file this environment could save — so the header/footer/favicon
currently use a CSS "chrome" text wordmark (`src/components/Logo.tsx`) and a
generated favicon (`src/app/icon.svg`) as a stand-in for the same mood. Drop
the real logo file into `public/brand/` and swap it into `Logo.tsx` and
`icon.svg` when you have it as a file.
