# Clifstone

E-commerce site for **Clifstone**, a Moroccan gothic streetwear-luxe brand
(watches, sunglasses, wallets, jewelry, accessories). Guest checkout only,
Cash on Delivery, free shipping, MAD currency, French/Arabic product content.

Stack: Next.js (App Router) + TypeScript + Tailwind CSS v4 + Prisma (SQLite) +
Zustand (cart) + a lightweight JWT-cookie admin auth (no external auth
provider needed).

## Getting started

```bash
npm install
cp .env.example .env   # then edit values as needed
npm run db:push        # creates the SQLite database from prisma/schema.prisma
npm run db:seed        # seeds categories, 4 products per category, admin user
npm run dev
```

Storefront: http://localhost:3000
Admin panel: http://localhost:3000/admin/login

Default admin login (from `.env` / seed — **change these in production**):

## Project structure

- `src/app/(store)/...` — storefront: homepage, `/shop/[category]`,
  `/product/[slug]`, `/cart`, `/checkout`, `/order/[id]`.
- `src/app/admin/...` — admin panel (protected by `src/proxy.ts`, the
  Next.js middleware/proxy convention): dashboard, product CRUD, order
  management.
- `src/app/api/...` — `/api/checkout` (guest order creation) and
  `/api/admin/*` (products, order status updates, CSV export).
- `prisma/schema.prisma` — `Category`, `Product`, `Order`, `OrderItem`,
  `AdminUser`, and `Counter` (backs sequential order numbers) models.
  `prisma/seed.ts` seeds everything, including product placeholder images
  generated by `scripts/generate-placeholders.mjs` into `public/products/`.

All product content (name, price, description, images, category, stock) is
editable from the admin panel — nothing is hardcoded in the frontend.

## Product images

Products ship with generated SVG placeholders so the store looks complete
out of the box. To use real photography, upload images anywhere (or drop
files into `public/products/`) and paste their URLs (one per line) into the
product form's "Images" field in the admin panel.

## WhatsApp order notifications

Every order is saved to the database regardless of what happens next. Per
project decision, notifications to **+212 640 848 752** use a **wa.me deep
link** (no Meta Business account / API token required):

- Right after a customer submits checkout, their browser opens a WhatsApp
  chat pre-filled with the full order summary, addressed to the store's
  number — they just tap send.
- The admin order detail page (`/admin/orders/[id]`) also has a
  "Envoyer / renvoyer sur WhatsApp" button that opens the same pre-filled
  message, for manual resend.

Message building lives in `src/lib/whatsapp.ts`. If you later get a Meta
WhatsApp Business/Cloud API account, swap `buildWhatsAppLink` for a
server-side `fetch` call to the Cloud API inside `src/app/api/checkout/route.ts`
— `META_WHATSAPP_TOKEN` / `META_WHATSAPP_PHONE_NUMBER_ID` env vars are
already reserved in `.env.example` for that.

## Order tracking

Every order gets a sequential, customer-friendly number (`CLF-000123`,
`src/lib/order-number.ts`) alongside its internal id — assigned atomically
via a `Counter` row in a transaction, since SQLite only supports
`autoincrement()` on the primary key.

- Shown to the customer on the order confirmation page and in the WhatsApp
  message.
- `/track` (linked from the header, footer, and confirmation page) lets a
  customer look up their order by number + phone (phone must match, so
  order numbers alone can't be used to snoop on other customers) and see a
  status timeline (Nouvelle → En traitement → Expédiée → Livrée, or
  Annulée) plus the carrier tracking number once shipped.
- Admins update status from `/admin/orders` or an order's detail page as
  usual; that status is what drives the tracking page.

## Ameex delivery integration

Ameex's public API details weren't available while building this, so the
integration is built in two layers:

1. **Always works today — CSV export.** `/admin/orders` has an "Export CSV
   (Ameex)" button (`GET /api/admin/orders/export`, optionally
   `?status=NEW`) with the standard columns Moroccan carriers ask for on
   manual bulk upload (recipient name, phone, city, address, product
   summary, quantity, COD amount, note, and now the `CLF-xxxxxx` order
   number as the reference column).
2. **Ready to activate — API scaffold.** `src/lib/delivery/` defines a
   `DeliveryProvider` interface and an `AmeexProvider` implementation
   (`src/lib/delivery/ameex.ts`) with a best-guess request shape (POST
   `{AMEEX_API_BASE_URL}/orders` with a bearer token). It's a **placeholder**
   — update the endpoint path, headers, and field names in that file once
   you have Ameex's real API docs. Until `AMEEX_API_BASE_URL` and
   `AMEEX_API_KEY` are set, the admin order page's "Envoyer à Ameex" button
   shows a clear "not configured" message instead of failing silently.

Either way, an order's detail page (`/admin/orders/[id]`) has a carrier
panel that either calls the Ameex API automatically, or lets an admin type
in a tracking number by hand (for when a shipment was created through
Ameex's own portal) — both paths mark the order `SHIPPED`, record the
carrier + tracking id, and immediately surface it on `/track` for the
customer. Set `AMEEX_TRACKING_URL_TEMPLATE` (e.g.
`https://ameex.ma/track/{id}`) once you know Ameex's own tracking page
format, and both the admin and customer tracking views will link out to it.

## Logo

The real Clifstone graffiti wordmark lives at
`public/brand/clifstone-logo-original.jpg` (the source photo) with two
derived assets checked in: `public/brand/logo-wordmark.webp` (used by
`src/components/Logo.tsx` in the header, footer, admin sidebar, and login
page) and `src/app/icon.png` / `apple-icon.png` (favicon / home-screen icon,
cropped to just the leading letterform since a favicon doesn't need to be
legible as full text).

If you get a higher-resolution version of the logo later, drop it in as
`public/brand/clifstone-logo-original.jpg` and re-run
`node scripts/crop-logo.mjs` to regenerate all three derived assets with the
same crop framing.
